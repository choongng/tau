### The questions

- **Why did the task stay open with the check passing, five times?**
  - The verdict comes from `_unread_cases` (L4850), which calls `_cases_test_reads` (L4755). The close prints it at L11273, and the not-done note goes through `_cases_close_problem` (L9046).
  - `_cases_test_reads` gathers names assigned from expressions that mention `cases.json` (so `CASES` and `here`'s joinpath expression count). Then it looks for a read call whose arguments mention one of those names. Its read calls are a Name `open`/`Path`, or an Attribute `read_text`/`Path`/`json.load(s)`. For `read_text` it also checks the receiver.
  - `CASES.open()` is an Attribute call named `open`, so it is not a read. `json.load(fh)` takes `fh`, which is a `with … as` target and not an Assign, so it is not a name from the data.
  - Offline: `with CASES.open() as fh: json.load(fh)` → False; `json.loads(CASES.read_text())` → True; `open(CASES)` → True. `.open()` on a path is the idiom most code uses.

Prompt-independent: yes. `Path.open()` and `with … as fh: json.load(fh)` are the common Python idioms for reading any data file, and the fix is purely about AST shape, with no file or domain names.
