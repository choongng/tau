## Failure classes

### [tau] A helper script the task's own worker wrote under a test directory is taken as "the code it judges", and the advised remedy cannot clear the refusal on an open task
Evidence: E16 to E122, 51 times: "pursuit_step: T0002 not run — scope holds known-answer data (tests/cases.json) and the code it judges (tests/casegen.py). Split it: first a task with only the data and its cases test in scope, passing locks=[tests/cases.json]; then the code in a later task."

Why it is wrong, and why it repeats:
- `_oracle_with_code_problem` (L4379) walks the directory scope `tests/` via `_scope_dir_files`, and counts any `.py` for which `_is_test_path` is False as source. `_is_test_path("tests/casegen.py")` is False, by R24's rule.
- No test imports casegen, and the check does not name it. The cases test imports `cobs`.
- The driver passed locks=[tests/cases.json, …] 59 times. They went to locks-pending.json, while the function reads only `_locked(goal)` (manifest, empty), so the data stayed "unlocked".
- The open-task branch in `_execute` (L10450) returns before any worker. So the notes "delete tests/casegen.py" (#33–#67) could never reach a worker, and the driver's `agent` was refused by the guard (E68).
- Offline on a copy of ~/cobs:
  - `_oracle_with_code_problem(["docs/","tests/"])` reproduces the text;
  - `_oracle_with_code_problem(["tests/cases.json","tests/test_case_data.py","tests/test_cases.py"])` is None.
  - So one call with that `scope` would have run a worker. No answer named it.

Action: in examples/extensions/beagle.py:
- `_oracle_with_code_problem`: count as "the code it judges" only a non-test source the scope's tests import (`_test_project_imports`) or the check names (`_check_path_words`). A non-test `.py` under a test directory that nothing imports is a helper. Leave it out of `source`, or name it as "a helper script; delete it or leave it out of scope".
- `_oracle_with_code_problem`: treat the task's own pending locks (`_pending_locks(goal, task)`) as locked for the purpose of this judgement. The pending lock is restored before each check, as a manifest lock is, so the advised `locks=` does what the text promises.
- `_execute`, in the open-task branch (`mixed = _oracle_with_code_problem(scope, goal)`, L10450): compute the narrowed scope, which is the scope's files minus the flagged source, and check it with the same function. Name the call that runs: `pursuit_step task=<id> scope=[…]` with notes to remove the helper. Do not say "Split it", which applies only to opening.
