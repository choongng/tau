## 2. Root causes, ranked by cost

### 2.1 The R40 own-copy detector misfired on a data-only test loader

This is tau, and it is **new**: it is not in mining.md.

**Cost:** about 13 min (steps 2–4), and it triggered the split behind §2.2. If the check had been judged correctly, T0002 would have closed at about 11:02. The witness was already PROVEN.

**Mechanism.** In beagle.py, `_cases_test_problem` (about line 5770) flags a file when all four of these hold:
- `_called_module_functions(tree)` is non-empty (line 5583). It returns any called non-test module-level function, so a `_load_cases()` loader counts.
- `answers` is set.
- The test does not import the project.
- `_answers_compared(...)` holds (line 5482). It treats names looped from any call as carriers, so `for case in _load_cases(): assert "result" in case` counts as a comparison.

The rule exists for tests that carry their own copy of the algorithm. Here it caught the very data test the step-1 message had asked for ("the test this check runs loads the data only").

The worker's 5f53adf tests/test_case_data.py is pure structural validation.

### 2.2 After the split, a tests/data-only route can never be proven

**Cost:** 11:10–12:22, about 70 min. It took 19 worker runs, 4 supersede chains and 4 infeasible closes (T0011, T0015, T0019, T0023).

**Mechanism.**
1. `_commit_before_split` (beagle.py around line 3958, R12, 52f09979) commits the parent's passing WIP. After the split, cases.json and both tests are in every child's opened commit.
2. Every child's natural check "already passes, before any work". To open a task at all, the driver must invent a fresh check file: test_cases_json.py, test_t0012_check.py, and so on.
3. `_prove` (line 10091) then has nothing to take away:
   - A WITNESS in a test file is refused ("the WITNESS is in a test file; name a defect in the code the test runs"). There was no code.
   - The absent-source fallback skips `.py` test paths. It also drops data files that are in the opened commit (`not _in_commit(opened, rel)`), so the cases.json that T0011 rewrote does not count.
   - `_locked_fix_reversion` needs locks in the manifest, and nothing was ever locked.
4. tau's own repeated advice, "This scope holds only tests and data, so the data file's absence is the proof" (11:14:09, 11:19:02, 12:22:36), cannot be met once the data file is committed. ## 4. Correctness spot check: cases.json against references/

**Committed 5f53adf (10 cases).** Every `source` is verbatim in the references.
- `seed_clock` (1,0): correct.
- `fork_seed` 1 → ([1,0],0) and ([0,1],0): correct, by split(1) = ((1,0),(0,1)).
- `event_on_seed` (1,0) → (1,1): correct, by grow(1,n) = (n+1,0).
- `join_sibling_clocks` ([1,0],0) + ([0,1],0) → (1,0): correct, since sum normalizes (1,0)+(0,1) to 1.
- `compare_concurrent` e=[1,1,0] vs [1,0,1]: correct, since neither leq holds.
- Weaknesses:
  - `event_then_compare` duplicates `compare_less_than` input for input.
  - `fork_then_event` performs no event; it is a fork of (1,1).
  - The tree encoding (`[n,l,r]` for events, `[l,r]` for ids) is undocumented.
  - There is no non-trivial event (fill/grow on a split id), and no nested-id join.

**Working copy (7 cases, rewritten by T0011's af5098de, uncommitted).**
- `join_two_seeds` joins (1,0) with (1,0) and expects (1,0). Two seeds have overlapping ids, and the paper requires disjoint ids (itc2008.txt:170–171, "non-overlapping graphs for any pair of id functions"). sum(1,1) has no rule. **This case is invalid.**
- Its `source` is also not verbatim, because of spacing in `sum((l1, r1), …)`. The same is true of `compare_equivalent`.
- The remaining cases are correct:
  - `compare_concurrent` (3,1,0) vs (3,0,2);
  - `compare_equivalent`: [1,0] vs [0,1], both with e=3. Ids are ignored, which is fine.
