## tau choong-dev (tag `choong/0.4.8.1`)

- **Refusal rewrites** (merge 1c54bb18, from `refusals-inventory.md`). Where the host knows the
  answer it repairs; where only the model does, the refusal names the one call that fixes it.
  Examples come from the project's own checks, never a fixed language:
  - pursuit_plan turns a title into its id;
  - a spawn on an open task with no commit of its own amends that task's check in place;
  - refused out-of-scope writes reach the driver with the widened `scope=[...]` call;
  - criteria are filled from the recorded intent;
  - a `pursuit_dispatch` after founding runs as `pursuit_step`;
  - a step on a waiting task steps the task it waits on;
  - a cases worker that left no markers is resumed (up to 2 times);
  - a missing scope is derived from the check's files;
  - every relayed beagle refusal ends with a tau call;
  - the example check comes from the project, and `_is_test_path` knows Go, JS/TS, JVM and Rust
    layouts.
  The tool schema texts are unchanged, because of the prefix cache.
- **Keep the best attempt** (merge 254dd1cf, upstream-asks 12):
  - Each check run is kept as `refs/tau/attempts/<task>/<n>`, from the host's check and from a
    worker's own runs of the check.
  - Each attempt gets a language-neutral figure: marked cases not named on a failure line.
  - Attempts are ranked: passing first, then the higher figure.
  - When the tree falls below the best attempt, the model is told the best attempt's ref and the
    `git diff` command, in the worker's tool result, the retry brief and the step result.
  - When a step ends below the best, it restores that attempt's scope files and runs the check
    again.
